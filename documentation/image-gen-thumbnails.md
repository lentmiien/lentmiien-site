# ComfyUI input and saved-gallery thumbnails

Workflow image cards and saved/pinned gallery cards use separate still-image previews. **Open** always targets the existing full-size URL. Audio, video, PDF, and text input previews retain their existing behavior. Failed, unauthorized, missing, unsupported, or corrupt thumbnails display “Preview unavailable”; there is no automatic original-image fallback.

## Endpoint contracts

| Site GET/HEAD endpoint | Source | Successful representation |
| --- | --- | --- |
| `/image_gen/api/files/input/thumbnail?path=<relative input path>` | Configured Gateway `GET /comfy/input/thumbnail?path=...` | Still WebP, within 512×512 |
| `/image_gen/api/good-images/:id/thumbnail` | The persisted GoodImage record's `filename` in local `public/img` | Still WebP, within 512×512 |

Gallery metadata adds `thumbnail_url` for ordinary and pinned records; existing `public_url`, `cached_url`, and `download_url` values are unchanged. There are no schema changes, migrations, backfills, startup conversions, or database writes for thumbnails. Listing records remains inexpensive. Files in `public/img` without a GoodImage record cannot be selected through the thumbnail endpoint.

The Gateway contract is fixed: identical relative paths and authentication to `/comfy/input/view`, orientation corrected, aspect ratio and transparency preserved, no enlargement, first animation frame, source-aware disk caching, ETag/Last-Modified revalidation, and non-2xx failures without original fallback. The site forwards `If-None-Match` and `If-Modified-Since`, accepts bodyless 304, forwards ETag/Last-Modified, and enforces `Cache-Control: private, no-cache`, WebP content type, inline disposition, and nosniff. It never forwards upstream cookies, redirects, public cache directives, or arbitrary disposition headers. Range is deliberately only used on the unchanged original `/image_gen/api/files/input/view` endpoint. Thumbnail query resizing options are rejected.

## Cache and work limits

`services/goodImageThumbnailService.js` exports `SETTINGS`. Production uses these fixed defaults (no new environment configuration):

- Cache: `<site>/cache/image-gen-thumbnails`, outside public static serving, created on demand. Directory mode 0700 and file mode 0600 for newly created entries. This expendable directory does not need a backup.
- Format version `v1`, maximum 512×512, WebP quality 80, auto-orientation, aspect/transparency retained, no enlargement, first frame only, metadata stripped.
- Supported local sources: PNG, JPEG, WebP, GIF, AVIF, TIFF; content must decode as an allowed raster format. SVG, PDFs, video, nonlocal URLs, unsafe names, directories, and symlinks are rejected. Legacy records without a supported durable local original show the placeholder.
- Maximum source size 100 MiB, decoded first-frame size 40 million pixels, derivative size 2 MiB, Sharp processing timeout 15 seconds. Reads use an inspected file descriptor and fixed-size buffer; source changes during conversion abort that request.
- Two concurrent cache operations/conversions, at most 32 queued operations, and in-flight coalescing for the same record/source in each process. Atomic writes use unique temporary files and rename. Multiple processes may duplicate work but cannot publish a partial file.
- Source identity includes record ID, filename, device/inode, byte size, nanosecond mtime and ctime, plus format version. Every request checks the local source before using a disk entry or returning 304. Overwriting the same filename invalidates its ETag, including same-size writes with restored mtime. ETags are the preferred validators; HTTP dates have only one-second precision.
- Cleanup runs lazily on requests, at most once per hour. Seven-day retention by creation/modification age, newest 4096 entries and 512 MiB targets; these are soft limits between cleanup passes. Old source versions and abandoned temporary files expire in this same namespace. No scan/conversion of public originals occurs. An idle site's expendable cache remains until another request or operator removal.
- Both endpoints share a 240-request/minute/principal limit and 32 simultaneous HTTP request limit per process. Saturation returns 429/503 and the UI placeholder. Input proxies enforce 2 MiB and a 30-second total deadline, in addition to existing Gateway header/idle timeouts and cancellation on disconnect. Gateway retains responsibility for its own conversion bounds/cache.

The application process needs read access to durable originals and write access to the private cache. Existing `COMFY_API_BASE`, `COMFY_API_KEY`, `COMFY_STREAM_HEADER_TIMEOUT_MS`, and `COMFY_STREAM_IDLE_TIMEOUT_MS` settings continue to apply. Node 24.20.0 and the already-installed Sharp dependency are used; dependencies are unchanged.

## Security contract and route registry

- **Zone/principals:** logged-in application sessions only; no machine principal or public access added. The existing app mount still requires the legacy `image_gen` feature grant. In addition, `utils/imageGenThumbnailPolicy.js` declares the new routes and semantic capabilities; `routes/image_gen.js` registers them ahead of the legacy wildcard file route through shared `requireCapabilities`/`authorization` controls.
- **Capabilities/assignments:** `comfy.inputs.read` and `comfy.gallery.read`. Admin receives both as an explicit capability bundle. Family/user/custom roles receive neither automatically and may receive explicit per-user or group grants through RoleModel. Legacy `image_gen` alone does not confer these new capabilities. Existing deployments used solely by admin need no grant changes. Access lookup errors fail closed.
- **Object scope:** explicitly admin-managed libraries. Each capability authorizes reads across its respective entire library, including historical records; these records and Gateway paths have no trustworthy owner field. There is no inferred ownership or request-supplied principal. A gallery thumbnail must resolve an existing GoodImage ID before selecting its local original. Input paths are bounded relative paths within the configured Gateway's input library, with confinement additionally enforced by Gateway. Missing records and invalid/unsafe sources return generic unavailable responses. No public-directory enumeration endpoint is added.
- **Data/storage:** derivatives are private; legacy originals retain their existing exposure. No changes to static middleware or public source URLs. Source and cache roots require lexical/realpath containment; final source/cache reads use no-follow descriptors and regular-file checks.
- **Mutations/CSRF:** GET/HEAD only, no browser mutation API; the derived disk cache is an internal read optimization. No CSRF exemption or new mutation route.
- **Output:** DOM element creation/textContent, fixed same-origin thumbnail endpoints, HTTP(S)-only explicit Open links, no inline handlers. Existing Graphite/Ember/Golden Amber theme tokens are retained. The thumbnail endpoints render no analytics.
- **Outbound:** only the configured authenticated Gateway endpoint for inputs; redirects rejected. Saved gallery thumbnails never download from Gateway, cached URLs, or arbitrary URLs.
- **Cache/privacy:** every conditional request passes authentication, capability, and record/source checks. Private browser caches must revalidate; shared/Cloudflare caches must not cache these endpoints. No new Cloudflare bypass or rule change required.
- **Logging:** actionable Gateway failures and local decode/storage/cleanup failures use the shared logger; messages omit source paths, image contents, prompts, provider payloads, and credentials. Client disconnects are not operational failures. Thumbnail requests deliberately omit raw API debug payload logging.
- **Negative coverage:** anonymous, family/user/missing or wrong capability, explicit grants, nonexistent record, malformed IDs/paths, traversal, symlinks, unsupported/corrupt/missing/oversized sources, decode/concurrency limits, conditional headers/304, changed sources, failed writes, disconnects, unsafe upstream headers, chunked oversize responses, and UI fallback without original loading.

## Deployment and rollback

Deploy **Gateway first**, verifying its fixed `/comfy/input/thumbnail` contract, then deploy this site commit through the normal release process. An older Gateway will return a failed thumbnail and the UI placeholder; the site will never fall back to downloading the original automatically. Open and non-image previews remain usable. No live Gateway compatibility or production deployment is performed by the implementation tests, which use synthetic fixtures.

The site-local gallery cache works independently of the Gateway update. Non-admin feature users need the appropriate semantic read capability as well as their existing `image_gen` grant. No production data migration or eager backfill is required. Existing public originals are neither moved nor re-exposed.

Rollback the site release normally if necessary; the private derivative cache may be left in place or removed while the app is stopped. Source files and database records are unaffected. Future encoder changes should bump the format version to invalidate old derivatives.

## GPT Image Studio and bulk output previews (October 2026)

The existing site route is `/gpt-image` (hyphen). This extension changes previews on that page, `/image_gen/bulk/:jobId`, and `/image_gen/bulk/:jobId/analytics`. Gateway is unchanged and is not involved in these new thumbnail requests.

### URL and source mapping

| Page / preview surface | Thumbnail GET/HEAD | Original URL retained | Trusted local source |
| --- | --- | --- | --- |
| `/gpt-image`: initial/paginated/filtered gallery, highlighted generation after redirect, selected-reference tray | `/gpt-image/api/images/:imageId/thumbnail` | Record `outputUrl`: `/gpt-image/media/gpt-image-private-<UUID>.<png\|jpg\|webp>` or historical `/img/<filename>`; **Open image** retains this value | Existing `GptImageGeneration` output record with matching `outputFileName`/`outputUrl`; private root from `GPT_IMAGE_STORAGE_DIR` (default `private_data/gpt-image`) or legacy `public/img` |
| `/image_gen/bulk/:jobId`: gallery and comparison matrix | `/image_gen/api/bulk/jobs/:jobId/prompts/:promptId/thumbnail` | Gallery image links retain the former preview's `cached_url` (`/imgen/<instance>/<filename>` or `/imgen/<filename>`), falling back to the existing `download_url`/`file_url` when absent. Matrix links and gallery **Open original** retain `/image_gen/api/files/output/<encoded filename>?instance_id=<instance>` (parameter omitted for older records), with the matrix's existing `file_url` fallback | Completed `BulkTestPrompt` belonging to the existing `BulkJob`; filename and prompt instance (falling back to job instance) select `public/imgen/<instance>/<filename>` or `public/imgen/<filename>` |
| `/image_gen/bulk/:jobId/analytics`: Top images and Low defect images grids | Same bulk endpoint above | Former preview's `cached_url`, otherwise existing `download_url`, unchanged | Same scoped bulk mapping above |

Bulk gallery/matrix rerenders after filters, variable changes, rating updates and job polling use the same thumbnail-only image renderer. Analytics has one asynchronous fetch per page load, no separate image chart, pin, or refresh timer; its charts/statistics remain unchanged. GPT generation redirects to the existing gallery; no extra result-card renderer exists. Persisted selected-reference IDs are retained, but stored preview URLs are replaced at read time with the record thumbnail endpoint, including selections made before this change. Like/select/remove controls remain outside original-image links. Bulk video behavior remains unchanged, including gallery/analytics playback controls; GIFs use a still first-frame thumbnail. All original image links open in a new tab with `rel="noopener noreferrer"`. Thumbnail failure or missing/invalid metadata yields a text placeholder, never an original-image request. CSS contains the image without cropping and uses the shared theme tokens.

### Shared implementation, cache and limits

`services/localImageThumbnailService.js` now owns the existing Sharp renderer/cache. `services/goodImageThumbnailService.js` is a compatibility adapter: existing GoodImage URLs, filename validation, cache namespace and v1 cache keys remain compatible. New outputs are never represented by GoodImage records.

New private derivative namespaces, created lazily:

- GPT private outputs: `<site>/cache/gpt-image-thumbnails/private`.
- GPT historical outputs: `<site>/cache/gpt-image-thumbnails/legacy`.
- Bulk outputs: `<site>/cache/bulk-image-thumbnails`.

Each renderer uses the same fixed settings listed above: 512×512 maximum, quality 80 WebP, orientation corrected, aspect/transparency retained, no enlargement, first animation frame, metadata stripped; 100 MiB source, 40 million decoded pixels, 2 MiB derivative, 15-second Sharp timeout, two active and 32 pending operations. Each namespace has its own seven-day/4096-entry/512 MiB soft cleanup budget and hourly lazy cleanup. Budget totals therefore grow with the additional namespaces. The shared `middleware/thumbnailLimits.js` applies a combined 240 requests/minute/principal and 32 simultaneous HTTP requests across input, saved-gallery, GPT and bulk thumbnails in each process. No new environment variables or packages are introduced.

Source versions include the instance-relative filename where applicable, record ID and device/inode/size/nanosecond mtime/ctime. Every cache/304 request still checks the source. Both source and cache roots/ancestors must be canonical; source instance directories and final files cannot be symlinks, and source hardlinks are rejected. Existing cache ancestors are checked before directory creation. Bounded file-descriptor reads and atomic writes remain shared. Directory names are limited to one safe instance segment of at most 128 characters; filenames are at most 255 characters, reject separators/control characters/colon/percent escapes, and require a supported raster extension. Historical filenames may contain spaces and Unicode. Sources with unsafe stored mappings, missing local bytes, unsupported formats, corrupt content or excessive size display the placeholder.

GET and HEAD return private revalidated WebP with ETag/Last-Modified, inline disposition, nosniff and bodyless HEAD/304. Error responses are generic and private/no-store. HTTP slots release on finish/disconnect, and controllers stop before conversion if already disconnected and do not send late success/error responses. A bounded conversion already in progress may complete its shared cache entry for other readers after disconnect; it does not start an outbound download. New thumbnail endpoints never call `ensureCached`, Gateway or original-file routes. Existing bulk listing metadata recovery for completed prompts lacking a filename remains unchanged; that legacy recovery can retrieve missing job outputs independently of thumbnail delivery.

### Security contract and registry additions

- **Feature/zone/principals:** local output thumbnails; logged-in application sessions only, no machine/anonymous access. Data is private derivative media; existing original visibility is unchanged.
- **GPT capability and scope:** `gpt_image.library.read`, registered as GET/HEAD `/api/images/:id/thumbnail` in `utils/gptImageAuthorizationPolicy.js`. The existing explicit bundles make every complete authenticated principal (admin/family/user/custom) a member of the shared library, as already approved for GPT Image. No owner inference or additional admin override. A persisted output record and exact local URL/filename mapping are required; orphan files, uploaded-reference-only filenames, arbitrary URLs and caller-selected paths cannot be requested through this endpoint.
- **Bulk capability and scope:** `comfy.bulk.read`, registered in `utils/imageGenThumbnailPolicy.js`. The library is explicitly **admin-managed**, because historical bulk jobs/prompts have no owner field. Admin receives the capability through its explicit bundle; family/user/custom roles require explicit RoleModel grants plus the existing parent `image_gen` permission. This capability authorizes the whole bulk library, not only jobs created by the caller. The endpoint verifies the parent and queries the child by `{ _id, job, status: 'Completed' }`. Wrong-parent/missing/deleted/noncompleted objects return the same 404. A caller cannot choose an instance, filename, bucket, source URL or resize settings; all query parameters are rejected.
- **Mutations/CSRF:** GET/HEAD read optimization only; no browser mutation or CSRF exception. Existing selection/rating/generation behavior is preserved.
- **Work/output/outbound:** bounded IDs and trusted record mappings, fixed raster rendering limits above; escaped Pug/DOM text and fixed same-origin thumbnail URLs, HTTP(S)-only new explicit original links. No outbound host, new static mount, startup conversion, original scan, DB write, migration or backfill for thumbnails.
- **Privacy/logging/retention:** authorization and record/source checks precede conditional responses; private/no-cache success and private/no-store failures; no analytics added. Shared logger reports actionable lookup/decode/storage/cleanup failures with opaque IDs/status/codes, without filenames, prompts, source paths or credentials. Derivatives expire lazily; deleting a record/source immediately prevents subsequent thumbnail responses, including 304, even if an expendable disk entry remains until cleanup.
- **Negative/regression coverage:** route integration with synthetic local rasters covers principal/capability denial and grants, shared GPT membership, parent-child query scope, invalid IDs/queries/stored paths, private/legacy/instance mappings, missing/corrupt/symlink/hardlink sources, safe errors, ETag/date/HEAD/source replacement and disconnects. Renderer tests cover disk reuse, overwrite invalidation, orientation/transparency/formats/first animation frame, pixel/byte/queue limits and failed writes. Pug/JSDOM tests cover initial/dynamic previews, original links/new tabs, reference restoration, filtering/rating/polling, analytics grids/charts, video controls and placeholders.

### Deployment readiness and caveats

This extension requires a **site release only**; the previously deployed Gateway remains compatible and unchanged. Implementation validation uses synthetic local fixtures, not production data. No deployment or production restart is performed here.

The application needs read access to the existing source roots and write access to the three new private cache namespaces. Keep caches outside static serving and exclude these authenticated thumbnail endpoints from Cloudflare/shared caching; honor private revalidation. GPT's existing private/no-store originals remain unchanged, with the documented private/no-cache exception only for thumbnails. Existing GPT storage trust/ACL checks continue to apply. No prewarming, manual backfill, database migration, provider sync or new configuration is needed. Non-admin bulk users need `comfy.bulk.read`; GPT users retain their existing library access.

Missing local bulk outputs intentionally do not trigger a full original transfer for preview. Users can still follow the unchanged original links. Initial cache misses cost bounded local decoding; saturation returns a placeholder, with retry on the next normal rerender/reload. Roll back the site release normally if necessary; private derivative caches can remain or be removed when the app is stopped. Do not delete originals. Encoder changes require a cache-version bump.
