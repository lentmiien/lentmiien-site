# AI Gateway service monitoring

Security contract: logged-in, admin-managed operational metadata (sensitive upstream data reduced to allowlisted status evidence). Interactive principals: admins; no machine principals. `ai_gateway.monitor.read` is bundled for admin only, with no family/user bundle. Existing `/admin` and Gateway music-admin gates remain enforced; explicit grants do not bypass them. No object IDs or request destinations are accepted. No new mutations, CSRF flows, media, database records, notifications, or automatic recovery. Browser output uses escaped Pug/textContent and private/no-store responses with analytics disabled. Fixed server-configured Gateway origin and four allowlisted GET paths use five-second timeouts, no redirects, 1 MiB response limits, a 15-second process-local sanitized cache, and single-flight refresh. Raw upstream bodies/errors, paths, job IDs, prompts and credentials are neither retained by monitoring nor returned/logged. Only fixed diagnostic labels and bounded catalog identifiers are shown. Commands are static operator templates. Warnings report endpoint/schema failure transitions without payloads. Cache expires by replacement/process exit; no persistent retention. Negative tests cover authorization, malformed/partial data, redaction, rendering and read-only requests. Existing controls and legacy charts remain separate.

Implementation uses the supplied Gateway contract (source b6c50a3c86c8bdf67914376ef2ef0eb462592971, not a deployed-version claim). `/health` can report degradation with HTTP 200. `/containers` defines catalog and lifecycle policy; aggregate health defines availability. Snapshot disagreement is reported as a transition/unknown, not a crash. No stop provenance, last-use, synthesis-success or per-service VRAM measurement is available. Only MPNet/Nomic ordinarily stay GPU-resident at idle; policy fields drive classification. Embeddings may yield to jobs, reservations, training or delayed warmup. CPU models may stay in RAM. Host VRAM is already graphed separately.

The page reuses initial dashboard snapshots and adds `/gpu/queue`; subsequent service refreshes use `/health`, `/containers`, `/gpu/queue`, `/gpu/reservation` only. Visible pages refresh every 30 seconds, with manual refresh, timeout, overlap prevention and a 60-second stale cutoff. Hidden pages pause polling. Unavailable or malformed snapshots replace prior health; independent valid sources remain usable with a partial-data banner. Raw error details are intentionally withheld: inspect host logs using the runbook. Successful readiness probes do not verify inference or synthesis. Busy aggregate probes take precedence over nested probe timeouts. Historical queue hook errors are labelled historical.

## Release and acceptance

No environment variables, dependencies, DB migrations or Gateway changes. Lennart deploys the site through the usual process; no production changes are made by this work. Private routes must continue bypassing edge caches. Roll back by reverting the monitoring commit and redeploying the site.

After deployment, sign in as admin and open `/admin/ai-gateway`. Verify fresh timestamps, service cards, queue/reservation ownership, copy buttons, narrow/mobile layout and existing controls. A running Voicevox with successful `/version` should show responsive, with model state unknown; retry one intended TTS request and listen separately. Confirm ordinary stopped recoverable GPU services show available on demand, model-unloaded OCR stays normal, and embeddings yielding to owned work are not alarms. Do not stop production services for acceptance: use local mocked fixtures for stopped Voicevox, degraded HTTP 200, missing/unknown inspection, stale monitoring and sensitive payloads. Simulate browser network failure and confirm cards are cleared and marked unavailable; after 60 seconds old data must not remain healthy. Switching back from a hidden tab should refresh. Recovery text must never execute host commands or trigger container/GPU mutations.

## Changed files and checks

- `services/aiGatewayMonitoringService.js`: strict snapshot validation, lifecycle interpretation, reduced diagnostic evidence, bounded GET collection, sanitized cache and transition warnings.
- `controllers/admincontroller.js`: reuse dashboard snapshots, fetch queue state, expose monitoring JSON, replace the static healthy summary, initialize monitoring lazily.
- `routes/admin.js`: preserve existing gates and add the monitoring read capability/route.
- `views/admin_ai_gateway.pug`, `views/includes/aiGatewayMonitoring.pug`: replace upstream OK/Issue cards with service monitoring and fixed recovery text; retain existing operator controls with a GPU reservation caution.
- `public/js/aiGatewayMonitoring.js`, `public/css/aiGateway.css`: safe DOM rendering, visible-tab polling, timeout, freshness expiry, back/forward-cache recovery, copy buttons and theme tokens.
- `tests/unit/aiGatewayMonitoring.test.js`, `tests/unit/aiGatewayMonitoringIntegration.test.js`, `tests/unit/aiGatewayMonitoringUi.test.js`: lifecycle/security/fetch/controller/route/Pug/DOM regressions using mocked Gateway responses.
- `tests/unit/musicDashboard.test.js`, `tests/unit/adminRoleManagement.test.js`: teach existing isolated test harnesses about the new imported service/middleware.
- This document: security contract, limits, release and acceptance instructions.

Validation commands: `npm test -- tests/unit/aiGatewayMonitoring.test.js tests/unit/aiGatewayMonitoringIntegration.test.js tests/unit/aiGatewayMonitoringUi.test.js --coverage=false --runInBand`, broader affected admin/Gateway/music suites, `npm test -- --runInBand`, and `git diff --check`. No application startup, deployment, production probe, TTS generation or service mutation is part of validation.
