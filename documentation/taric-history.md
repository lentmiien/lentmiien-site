# TARIC history, filtered JAN export and local enrichment

For the complete review → export → offline CSV → manual training workflow, read [the dataset user guide](taric-dataset-guide.md), also available privately at `/admin/taric/history/guide`. The converter is now implemented; source JSONL itself remains code-only candidates and requires explicit descriptions for Qwen conversion.

## Security contract

- Feature: private request/outcome history, explicit human label review, candidate export preparation, filtered JAN export and user-started local reprocessing.
- Zone: logged-in. Interactive principals: holders of `taric.tool.manage`; admin bundle only by default, no family/user default grant. Machine principals: none.
- Classification: private. Scope: explicitly admin-managed requests under the server's `taric_settings/tool.owner`, across integration and browser principals. Foreign owners are never joined, counted, reviewed or exported. No caller-selected owner. The existing semantic middleware and `adminPrincipal` both check current authority.
- Mutations: shared session CSRF header, POST, strict JSON; actor from session principal. Read-only GETs do not enqueue work or contact providers.
- Limits: 2,000 filtered live requests plus archived reviewed cases per configured owner, 2,000 related verified conflict peers, 32 MiB combined projected population, 50 rows/page, 100 revisions/request, 128 KiB canonical source JSON per revision, 2,000-character review note, 255-character approved description; 200 export rows, 8 MiB JSONL, 100 published independent benchmarks / 50,000 cases. Database reads and review CAS have 2-second server deadlines. Existing admin rate limit and a two-operation concurrency cap per application instance apply. Limit failures fail closed with an explicit explanation; no partial statistics or conflict scan.
- Rendering: escaped Pug and DOM textContent, no provider blobs/hidden reasoning/credentials, no analytics, local assets, existing admin CSP. Cache: private/no-store, no-referrer, nosniff, noindex.
- Storage: separate server-owned review/audit and immutable export documents in private MongoDB, no filesystem artifacts. Human verification authorizes private retention of canonical source snapshots until operator retirement/deletion; no new TTL. Existing unverified raw requests/outcomes still expire after 90 days; user-started local batch plans and local revision sources have explicit private retention without TTL. Verified snapshots bound to final immutable feedback remain accessible and exportable after raw expiry; proposal-only archives remain stale/ineligible. See retention/deletion policy below.
- Outbound services: JAN export, previews and history reads have none. Explicitly started local reprocessing uses only the existing configured private Gateway owned-session API for test inference; AmiAmi facts come exclusively from local MongoDB. No GCS calls/callbacks, scraping, importer execution, training or online factual fallback. Logging: shared logger, operation/status only; never facts, notes or output payloads. DB failures produce 503, never empty successful statistics.
- Negative tests: session/capability/CSRF, owner scope, unknown/operator parameters, bounds, stale revisions/source, unvalidated proposals, immutable feedback, snapshot mismatch and output field allowlists.
- Migration: idempotent bootstrap ensures eleven TARIC collections, adding `taric_reprocess_runs` and optional local revision fields/indexes to reviews. No automatic data migration, verification, credential rotation, benchmark selection, training or GCS changes. Local batches use the existing worker lease; normal-mode gate rules are unchanged. Cloudflare must not cache these paths. Rollback removes navigation/routes; retain audit collections.

## Semantics

Verification is a human label attestation, not official TARIC validation or training approval. Ten-digit syntax is checked; catalog membership is contextual only. Review defaults to final human feedback. Without feedback, an accepted model suggestion requires explicit target confirmation. A correction requires an existing target, a note/source and a separate confirmation. Rejected diagnostic proposals cannot supply the default target. Description approval is always separate, never inherited from a model.

Every review appends a revision using single-document CAS, binding a hash of allowlisted source inputs, factual evidence, outcome, proposal, provenance and source dates. Arrival of any feedback, even an agreeing code, makes an earlier review stale. Concurrent source changes are detected on subsequent reads; a saved review does not lock immutable request/outcome collections. Active requests cannot be reviewed. The current source hash and expected revision must match; audit history is never rewritten. A stale verified revision remains in the audit but is ineligible. Each verification now freezes the full allowlisted canonical source in that revision; subsequent revisions also retain their displayed source once a case has been verified. Model mutation guards prohibit replacing prior audit entries. At 100 revisions, the API returns `413 REVIEW_REVISION_LIMIT`; it never truncates audit. Repeating an explicit Verify is a new human attestation with a new timestamp/revision, not a no-op or automatic bulk approval.

Profile `reviewed-code-candidates/1` needs a current verified target, captured full item name, descriptive name, and six-digit original HS. Specifications are optional and missingness is preserved. Approved description is optional; missing description warns that offline conversion to the current adapter's mandatory-description target requires explicit approval. These are source candidates, not trainer-ready Qwen/LoRA files.

Conflicts are checked against indexed related verified reviews even outside the requested base filters (plus a bounded fallback for legacy reviews without identity keys): active current verified labels disagreeing within a JAN group or exact normalized canonical input group are derived as needs-review and excluded. Same-JAN changed facts remain distinct dedupe records but share a split group; contradictions are conservatively blocked until a reviewer explicitly withdraws/corrects a label. No source-applicability override or semantic near-duplicate detector is claimed. Exact duplicate inputs choose the latest verification, then stable request ID. NFKC/case/whitespace normalization is only for identity; exported facts retain their exact source values. Published, uncontaminated, independent release-eligible benchmark overlap/source/group hashes are checked; v0 is not a holdout. Unknown identities/paraphrases still need human checks.

Selector `reviewed-selector/1`: newest verification first or balanced by TARIC (lexicographic code round-robin, newest inside each code); default limit 100 and per-code cap 20, maxima 200 and 100. These are bounded pilot defaults, not optimized training policy. No duplication, oversampling, fabricated classes, split assignment or augmentation.

Preview is read-only POST and returns a digest of the bounded base-filtered source population, related review/conflict peers, holdouts, filters, options and selection. Download POST recomputes and compares it, then repeats a population check before freezing those exact rows. A change returns 409 and requires a new preview. The manifest records its validation cutoff, source/review hashes, options, exclusion decisions, algorithm/profile and SHA-256 of the exact candidate JSONL lines. The first JSONL line is a `reviewed-taric-export/1` manifest, remaining lines are `reviewed-code-candidates/1` candidates. Each row includes the complete canonical `source` and `review` objects: the repository canonical JSON hash reproduces `sourceHash` and `reviewHash` without database joins. The source includes exact inputs, facts/missingness, accepted suggestion or rejected diagnostic, final feedback, source timestamps and captured provenance. `sourceStorage` distinguishes live requests from archived reviews. These are not ready-to-train Qwen CSV files. A single document stores the exact complete JSONL and its SHA-256; no transaction/replica set needed. The cutoff is the final observed snapshot, not a cross-collection transaction or promise that no later edits can occur. Subsequent reviews do not rewrite frozen exports.

History statistics and filters cover logical live requests and retained review/local-revision cases only, never benchmark attempts. A live request and its retained review count once. Cards separately report live requests and archived reviewed sources; archived feedback represents the final feedback captured at review, not live outcome-collection activity. All timestamps/date boundaries are UTC (date-to inclusive day). Feedback shares use final-feedback count as denominator; they are not model accuracy. Cursor is `(createdAt, request ID)` descending and requires the returned population `snapshot`; changes return 409 rather than silently paginating a different population. Statistics and preview/export use the same final filters, not just the page. Indexed UTC date/JAN/mode/request-status predicates apply before the 2,000-case check and lookups for both live and archived sources. Other derived filters apply after bounded classification. Limit errors instruct the operator to narrow dates/JAN/mode/status; a large related conflict group or legacy review population can still require retirement/scaling. Reads use bounded aggregate joins, not application N+1 queries. Request IDs are strings, including lookup predicates; live dates are BSON dates and snapshot dates are canonical UTC strings. Upstream application/run/revision is not persisted by the current schema and is shown as unknown.

## Retention, source freshness and operator deletion

- A human verification captures exact canonical source facts and provenance (not credentials, hidden reasoning, provider blobs or raw transport), target, separately approved description or null, reviewer/time/note, feedback ID/hash and source hash in a single atomic review revision. The 128 KiB source bound and 100-revision cap keep the document below Mongo's 16 MiB limit, including latest/audit copies. Oversize sources fail explicitly instead of dropping facts.
- A snapshot with final feedback bound at verification has a closed outcome: the API permits one immutable final outcome per request. Requests/outcome facts are immutable in normal operation; outcome expiry is later than parent request expiry. Once the parent expires, feedback API calls cannot find it. This is the retention proof for exporting the canonical archived source; it is not a claim that an expired raw source is currently being checked.
- Verification before feedback is provisional for retention. Any later feedback, including agreeing feedback, makes its live source hash stale. After raw deletion, a snapshot without its own final feedback ID/hash is **always stale/ineligible**, even if nobody observed the intervening feedback. Reads do not mutate the audit. Such an archive cannot be reverified through an expired parent; resolve/reverify against final feedback while the parent exists, or create a new factual request and explicitly review it. No automatic promotion or fabricated final choice occurs.
- Existing hash-only reviews from `edc5cc2` are not silently upgraded. Their live detail warns `legacy_review_has_no_retained_source_reverify_before_expiry`. Lennart must legitimately re-review intended long-term cases before expiry. Already expired facts cannot be reconstructed from hashes. Frozen exports remain their original artifacts.
- Unreviewed raw data keeps its original 90-day TTL. Outside user-started local reprocessing, snapshots exist only after explicit verification, and remain in the private audit even after Needs review, Excluded or Unreviewed removes future candidate eligibility. They do not become machine API/raw-history records. Missing full name/category/HS6 still blocks the candidate profile; a verified target never supplies missing input facts.
- Withdrawal does not rewrite previously frozen/downloaded exports. To retire a case, use Needs review/Excluded with a reason. To **physically purge** it, an authorized operator must quiesce all Site writers/requests first, record an external non-content deletion receipt (owner, request/export IDs, actor/time/reason), delete the exact owner-scoped parent request and final outcome, delete the exact owner/request review document (all snapshots/audit), then delete whole owner-scoped exports referencing that request via `taric_exports.requests`. Also delete whole owner-scoped `taric_reprocess_runs` documents whose `cases.id` or `skipped.id` references the request, including planned/unfinished jobs; do not leave frozen originals/evidence in batch records. Local sources, original snapshots and local audit are inside the deleted review document. A batch can reference several cases: retire that complete batch record, preserving other cases’ independent review/local source records. Delete whole exports, never edit immutable JSONL/checksums. Pre-fix exports lack this index field and need a private operator inventory of their JSONL to identify affected export IDs. Apply the same policy to backups and downloaded copies; the application cannot recall downloads. If a case has exhausted 100 audit revisions, quiesce and purge/retire it through this operator process rather than resetting its counter. Resume only after scoped absence checks. There is no automatic purge or new deletion UI, and no tombstone retains facts after physical purge. Random request IDs are not reused; removing the parent prevents subsequent outcome writes.

## Filtered JAN export and local re-do (2026-09-25)

Both actions use the same strict owner-scoped history filters across **all pages**. The candidate selector's verified-only rules, 200-row selection limit and per-code caps do **not** apply to JAN export. The base history cap remains 2,000 cases / 32 MiB and fails with 413, never partial output. JAN preview counts filtered rows, distinct valid JANs, duplicates and missing/invalid strings. Only literal 8/13 decimal-digit strings are exported, sorted lexically, deduplicated, UTF-8 `jan` CSV. Import that column as TEXT in spreadsheets to retain leading zeros. No checksum/prefix rule, formulas or extra product fields. Preview and download are CSRF POSTs; download recomputes the full source/review/filter snapshot and returns 409 on change. JAN export creates no database/file/audit snapshot and uses private/no-store headers with a fixed safe filename.

Routes under `/admin/taric/history` (all require session capability `taric.tool.manage`, server-derived owner, shared CSRF for POST; API keys have no authority):

| Method/path | Behavior |
| --- | --- |
| POST `/jan/preview` | `{filters}` → counts, sorted JANs, snapshot hash |
| POST `/jan/download` | `{filters, expectedSnapshotHash}` → private CSV or 409 |
| POST `/reprocess/preview` | `{filters}` → local eligibility, exact candidate IDs/JANs/names/unchanged human codes and skip reasons; no mutation/Gateway call |
| POST `/reprocess/start` | `{filters, expectedSnapshotHash, token, confirm:true}` → durable job, 202 while active; token is 32–64 lowercase hex, bounded idempotency |
| GET `/reprocess/:batch` | Owner-scoped progress, per-case outcomes, distinct attempted/valid counts, review link |
| POST `/reprocess/:batch/cancel` | `{confirm:true}` stops future cases; no force cancellation/rollback |

No arbitrary ID list, actor/owner override, adapter, system prompt, selected code or replacement feedback is accepted. Bodies are 4 KiB (cancel 1 KiB). History and batch action concurrency each cap at two per instance. Local lookup has a 60-second overall deadline plus the existing per-query deadline. A job freezes at most 200 eligible cases / 8 MiB of source/evidence/settings, with up to 2,000 skip decisions. Failure is explicit; narrow filters. Jobs expire for dispatch after 24 hours but their private records do not expire. Only one active local batch per owner is allowed by Mongo unique index. There is no scheduler-created batch on page load, bootstrap or deploy.

Eligibility requires a terminal logical case, final immutable human feedback, original valid JAN and missing actual item name (or a prior local model failure). Stored Verified and Excluded reviews are protected, including stale verified reviews. To intentionally redo one, first explicitly withdraw verification using the existing review form with a reason; the old attestation/correction remains in its audit. Archived final-feedback-bound sources can be redone when the retained source contains sufficient JAN/category/HS; unsupported stale/proposal-only archives are skipped. Missing JAN, no final feedback, running duplicate, already-present item data, verified/excluded protection, no local item yet, ambiguous JAN and local revision exhaustion have distinct reasons. Zero eligible cases cannot start/reserve a session.

Only the local AmiAmi collection is read, with no fetch fallback or source writes. An original **resolved evidence gcode**, when still present and agreeing with the JAN, can disambiguate; an unproven caller item code cannot select an arbitrary imported record. Otherwise a JAN must identify exactly one gcode. A genuine stored item name is required; specifications and other absent facts remain absent. Original descriptive category and original HS are preserved. Evidence retains its existing hash, lookup method, timestamp, optional scode semantics and missingness; local revision capture has a separate actor/time. No facts are inferred from JAN/category/model text.

The durable batch is separate from `taric_runs`/`taric_attempts`: no score, release eligibility, API usage or feedback clone. Each planned case freezes root request ID, source/hash, review/local revision numbers, original feedback ID/hash and local evidence before inference. A durable `claiming` state precedes the atomic per-case claim. Review and local pointer changes share the `taric_reviews` single-document CAS, so a concurrent review wins or makes the case explicitly stale. Reads, review, statistics, candidate export and hashes all resolve the same latest bound local source. Machine request GET/idempotent replay still returns the original request result. Original mode/status/error remain distinct from `localReprocess.state/error`; updated suggestion/diagnostic and facts are the local attempt. Detail exposes the unchanged original and append-only local timeline. A changed source cannot reuse the previous verification or description approval. No synthetic human audit entries are written. Existing training corrections remain in the review audit; the form still defaults to the original human feedback and requires a new deliberate correction if appropriate.

The existing fenced Mongo inference lease, private capability cache, warm-session client, correlation reconciliation and owned cleanup are reused. Interactive requests get priority at each case boundary; benchmark jobs keep their existing scheduler priority. Within a slice, sequential cases share one session and renew its idle lease. Rotation happens for the existing 900-second hard budget / 260-second next-case safety reserve, interactive priority or reconciled remote state, not an arbitrary 8-case timer. Gateway has a 256-operation limit; this batch's 200-case maximum fits. Generation/transport timeouts and the existing 100-second cleanup polling budget are unchanged. Current server test adapter/template/catalog/config fingerprint is frozen; changes stop the job. Normal release stays closed unless its separate existing qualifications are met. An implementation fingerprint change requires legitimate normal-mode requalification; bootstrap never qualifies anything.

Per-case states include planned, claiming, running, recorded, enriched, model_failed, stale, cancelled and not_attempted. Job states are queued/running/complete/failed/cancelled/recovery_required. “Complete” means all planned cases have outcomes, not that all predictions succeeded or any labels were verified. A catalog rejection, invalid output, definite provider failure or lost acknowledgement retains refreshed facts and unchanged final human code. Existing bounded visible test diagnostics are retained in the local audit; credentials, tool envelopes and hidden reasoning fields are not stored. Definite errors continue after correlated idle proof. A lost response is recorded once and never blindly regenerated. Unproved idle/cleanup holds the existing global control. ADMISSION_BUSY before generation retains facts and reports zero attempts, with no false hold or foreign-reservation deletion.

On restart, an interrupted claimed operation becomes uncertain/interrupted, its planned facts are retained, unattempted cases stop, and no private owner token is invented. Recovery uses the manager's existing read-status → cancel pending → exclusive owned cleanup flow, including OWNERSHIP_LOST. Cancel-pending now includes local jobs and finalizes any retained attempted facts under that recovery lease. A fresh preview/new token is required for a new batch; no automatic replay of an uncertain attempt. Already enriched model failures can be retried explicitly by removing `missing=yes`, keeping `review=unreviewed`/`needs_review` as appropriate and choosing the local `model_failed` filter. Manual review can also verify their facts/target without trusting the model.

Local revision retention is an explicit consequence of **Start**, not human verification. Frozen batch plans, the original canonical source and up to 10 local revision snapshots per case persist privately until scoped operator purge, including unreviewed/failed-generation revisions and sources whose raw parent expires. Review history still has its independent 100-revision cap and each canonical source its 128 KiB bound. No quiet deletion or unlimited per-case retries. New review indexes: `review_local_date`, `review_local_jan`, `review_local_mode`, `review_local_state`. New collection indexes: `local_batch_idempotency`, `one_active_local_batch`, `local_batch_chronology`, `local_batch_case_purge`. The latter indexes frozen case references for operator deletion; also inspect the bounded skipped IDs. No new environment variables or dependencies. Retain both review and batch collections on rollback.

Older converters reject new fields rather than silently mislabeling; deploy/pull the matching converter before using enriched exports. Source/review hashes include the new provenance. The candidate target remains the explicitly reviewed human target, never the new model proposal; approved description remains separately required for Qwen CSV.
