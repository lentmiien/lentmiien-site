### Release notes and security scope

The [client](../public/js/miien.js) now keeps separate upload and transcription deadlines. The upload bound starts from the reservation's remaining duration, capped at 60 seconds plus 15 seconds observation margin. Only a validated, same-handle `transcribing` observation can adopt the transcription budget once (remaining duration at most 3,600,000 ms plus the same margin). Repeated reads may shorten their phase deadline but cannot extend it; `transcribing` cannot return to `uploading`. Invalid status, handle or pending duration fails locally. One independent **3,660,000 ms (61-minute) watchdog starts before reservation** and is never restarted by phase changes or polls. These are local duration comparisons, not browser/Gateway wall-clock alignment.

This remains within the existing **logged-in** [ASR security contract](#miien-only-lifecycle-and-security-contract). No server, route, admission model, capability, CSRF, ownership, dependency, environment setting or chat-data migration changes in this fix. Reservation/upload still occur once, uncertain transport polls only that handle, and duplicate upstream admission remains guarded by the existing server. Stop, hide, pagehide, Send/new pending turn and newer recording invalidate stale results; successful text appends once to the current editable draft, followed by best-effort acknowledgment, with no automatic Send. Fail-closed durable admission, existing TTS/backpressure, mouth motion, artwork and phone layout are preserved.

### Known limits, recovery and human acceptance checklist

Handles/results remain **in memory**; a restart loses them, a different worker cannot retrieve them, and reload does not restore an unsaved draft/transcript. Stop/hide invalidates locally and does not cancel accepted Gateway work. A lost acknowledgment falls back to result retention. The 4,000-character combined draft limit still applies. A whole-site history outage can cancel local ASR. Browser/device permission, actual latency/quality and physical phone keyboard behavior still require human testing.

**Unknown upstream settlement retains its durable slot indefinitely.** A restart or transport failure can orphan slots, including a crash before dispatch. Two orphan locks can block all Miien ASR while ordinary text remains available. Deadline expiry, retention, browser cancellation, elapsed time, an empty local job map and GPU idle are **not proof of Gateway settlement**. A deploy/rollback/restart does not safely clear locks or recover results.

Recovery requires an operator to **quiesce all app workers capable of admitting/dispatching ASR**, independently confirm the corresponding Gateway work is neither queued nor running and has settled, then remove **only the individually verified matching ASR slot/job record**, guarded by both slot `_id` and `jobId`. The site UUID is not a Gateway trace ID; account for the previously reported clock offset without inventing a current offset. If correspondence/settlement cannot be proved, leave the lock held and use text. No bulk clearing, automatic expiry, speculative TTL, or clearing `miien_speech_slots` as ASR recovery. Resume workers only through the normal controlled procedure. Rollback uses the previously approved artifact and the same quiescence/settlement rules; it cannot be treated as admission cleanup.

### Miien-only lifecycle and security contract

- **Zone/principals/capabilities:** logged-in; private audio/transcript and conversation data. No machine principals or admin object override. Every reservation, upload, status/result and discard requires `chat.conversation.read`, `chat.conversation.write`, and `chat.audio.transcribe`; admin has the existing bundle, family/user need explicit grants. Current authenticated identity supplies the immutable job owner, and every operation checks the existing single-member parent conversation. Identity/capabilities and membership are reloaded immediately before upstream dispatch and before retaining a result.
- **Browser mutations:** `POST /:id/transcribe` with `{}` reserves a server-generated handle without ASR work. `POST /:id/transcribe/:jobId/audio` uploads one validated recording and returns 202 without awaiting Gateway. `GET /:id/transcribe/:jobId` is read-only, repeats status and (only when ready) the result. `POST /:id/transcribe/:jobId` with `{action: "cancel" | "acknowledge"}` discards private text. Every POST uses shared CSRF/Origin/Fetch Metadata protection and the existing 12 mutations/minute limiter; the subtree's 100 requests/minute also remains. A complete successful microphone operation uses three mutations. GET cannot reserve, upload, consume or cancel.
- **Validation/output/cache:** reservation/discard field allowlists, opaque UUID handles, bounded JSON parser, private/no-store/nosniff/no-referrer/CSP responses. Missing and foreign handles both give the same generic 404, including after restart/expiry; knowing a handle gives no access. The upload is canonical mono PCM WAV, 16 kHz/16-bit, at most 60 seconds / **1,920,044 bytes** with header/alignment/byte-count validation. Compressed uploads are rejected. Browser capture still caps encoded chunks at 4 MiB and stops at 59 seconds before conversion. Result text is at most 4,000 characters and is assigned through the textarea's value, never HTML or automatically sent.
- **Work/admission:** [local lifecycle helper](../utils/miienTranscriptionJobs.js), not a new hosted service or general queue. Two fixed global durable slots and a unique principal index enforce **one outstanding request per user, two globally**, independent of Anny admission and across workers/restarts. Admission is reserved before raw parsing, and duplicate/concurrent uploads to a handle never dispatch again. Eight retained jobs per process bound status/result memory. At most two upload/Gateway buffers are active; provider/form-data buffers remain bounded by the existing private ASR limits. New [miien_asr_slot model](../models/miien_asr_slot.js) stores only slot/job/principal/conversation IDs and start time, never speech, transcripts, filenames or credentials. Explicit index initialization must succeed before admission. It has **no TTL**.
- **Deadlines/retention:** reservations and unfinished uploads expire after 60 seconds; active slow uploads are closed. `MIIEN_ASR_DEADLINE_MS` defaults to **2,800,000 ms (46m40s)**, covering the supplied 900+1,800-second allowances with 100 seconds margin; accepted range 2,700,000–3,600,000 ms. The Miien-only ASR instance and independent job abort watchdog use this total deadline. `MIIEN_ASR_RETENTION_MS` defaults to **300,000 ms (5 minutes)**, accepted range 60,000–600,000 ms. Invalid/noninteger/out-of-range configuration uses finite defaults. Ready text is immediately cleared on acknowledgment/cancel, otherwise scheduled expiry clears it without requiring a later read. Terminal metadata remains only through that retention period. No site audio/transcript file or browser persistent ASR handle/result is created. Gateway's own retention is outside this change.
- **Cancellation/uncertainty:** cancelling local ASR invalidates callbacks, stops polling and best-effort discards the site's result. It does **not** abort an accepted upstream request or release its capacity. The result is ignored and discarded when work settles. Complete upstream HTTP success or definite validation rejection (400/404/422) can release admission; transport errors, timeouts, redirects, oversized responses and uncertain server failures retain the durable slot for operator inspection. The independent deadline stops the site's outbound wait; it cannot prove Gateway stopped. No automatic POST retry occurs. Expired/deleted handles cannot be uploaded again, so retrying an old upload cannot recreate work.
- **Operational diagnostics:** `utils/logger` warning/error entries under `chat5_miien_asr` contain only the site's opaque job ID, elapsed milliseconds, allowlisted transport error code, bounded HTTP status, abort category and upstream uncertainty, plus actionable fixed messages. Upload disconnection before dispatch and admission-cleanup failures are logged safely. No raw error/provider payload, speech, transcript, private chat, filename or token is logged; private ASR debug payload logging stays disabled. The existing client contract does not surface Gateway's job/trace identifier: the site job ID correlates site operations only and must not be presented as a Gateway trace match. No success/per-poll logs are added.

### Browser behavior and explicit limitations

Recording, preparing/uploading, waiting for upload response, transcribing (possibly waiting for other Gateway audio work), reconnecting and terminal failures have distinct status details. No queue position or confirmed processing start is claimed. Short browser requests use 15 seconds for reservation/status/discard and 30 seconds for upload. Status polls occur five seconds after the prior read. They use the server's remaining duration rather than comparing browser/Gateway wall clocks, with 15 seconds observation margin and an independent maximum 3,660,000 ms watchdog. Polling is serial and bounded by these deadlines. An uncertain upload response leads only to GETs for that handle; a missing upload/expired/lost job requires a new explicit recording, never automatic re-upload. Transient ASR status failures can reconnect within the same bound.

The transcript is appended **once per active recording** to the exact current draft, preserving edits made during the wait and enforcing the combined 4,000-character bound. It stays editable and unsent. Read responses may repeat until acknowledgment, so this is guarded browser application plus idempotent cleanup, not a claim of exactly-once delivery over an unreliable network. Stop, Send, an observed new pending turn, a newer recording, hiding the tab and pagehide invalidate old results. Accepted hidden-tab behavior is preserved: **ASR is cancelled locally on hide, not silently resumed or appended on return**. History-refresh failure also continues to stop local audio/ASR and require fresh history before voice playback; a full network outage can therefore end local ASR instead of merely pausing it. Best-effort keepalive cancel/ack may be lost, in which case server retention/deadlines apply. Old TTS stays suppressed through microphone work; explicit Send/Replay and the existing latest-voice backpressure rules retain their accepted behavior.

ASR job state/results are **process-local and nonpersistent**. Reload restores saved conversation history, not microphone drafts or an unreviewed transcript. Restart loses result handles; a different worker cannot return another worker's in-memory result. Deploy only after verifying one app worker or sticky routing for all reservation/upload/poll/discard requests; the supplied production inspection did not establish that topology. Durable capacity still applies across workers, but this is not cross-worker result storage or restart recovery. A crash can leave a conservative admission lock even before dispatch. Ambiguous admission does not automatically reopen after retention/deadline: an operator must first quiesce all ASR-capable app workers and independently confirm Gateway settlement before deleting only the matching record in `miien_asr_slots`. Never clear Anny's `miien_speech_slot` as ASR cleanup. Cleanup/index failures fail closed; text chat stays available.

Shared `services/asrApiService.js`, ordinary Chat5, Anny speech/admission/text preparation, mouth/motion, all artwork and smartphone CSS/Pug are unchanged. Only the Miien controller's ASR instance has the longer timeout; ordinary Whisper remains at its existing 300,000 ms default and other model defaults remain compatible.

### Fix and bounds

- Before a new Anny submission, the adapter GETs `/:id/speech-admission/:messageId`. The response is only `{ state: 'available' | 'occupied' | 'blocked' | 'full' }`, after authorized saved-message validation and speech preparation. It contains no other principal's job ID, content, conversation or deadline. The read does not create jobs, mutate slots, prune audio, contact Gateway or reserve capacity.
- `occupied` means this process has a known active job. The latest eligible reply stays in one browser-local wait, with truthful “Waiting for previous voice generation before preparing the latest reply” details and the existing preparation activity/mouth-rest state. Captions/history/drafts remain immediately available. No B synthesis POST is made while that read reports occupied. On release, the next read admits B through the normal POST and existing single-flight/authorization checks. A's old callbacks/audio stay invalidated.
- C supersedes waiting B by replacing the adapter generation; only C remains eligible. Explicit Send restores automatic eligibility under the existing room rules; Replay can initiate a fresh manual wait. Stop, starting microphone permission, hiding, pagehide/disposal, disabling automatic speech, switching voice/mode, and a newer reply invalidate timers, requests and callbacks. Pending wait intent is never stored or recovered on tab return/reload. Returning to the tab cannot resume its automatic speech; explicit Replay remains available after fresh history.
- Wait is bounded by **20 minutes and at most 240 capacity reads**, five seconds apart after completion, with existing 15-second request timeouts. Deadline is checked before and after reads and has its own watchdog. Once a job is accepted, its existing independent 20-minute synthesis deadline and three-minute playback cap apply. Browser timer suspension can delay displayed timeout feedback; generation/visibility guards still forbid a revoked POST or playback. There is no server queue, fairness guarantee or persistent pending reply.
- Capacity is a hint: another tab/process may acquire admission before POST. Only the typed service rejection **HTTP 429 + `code: 'speech_admission_occupied'`**, emitted before a new job is accepted, permits one automatic reattempt. That reattempt waits through GETs and is at least **60 seconds after the first POST**, with at most **two POST attempts per eligible invocation**. Accepted jobs, generic route/storage/quota 429s, validation/permission/session failures, network/uncertain submission failures, malformed capacity responses and failed status/audio requests are never automatically resubmitted. Normal A → B → C supersession therefore sends only A and the winning reply's synthesis POSTs; rapid explicit requests across tabs still share the unchanged rate limits.
- `blocked` covers a local job past its deadline or a durable slot without a known local active job (including uncertain work, crash residue or another worker). This terminates the wait with operator guidance; it never clears or bypasses the global slot. `full` terminates with a storage-specific message. Proven A validation failure can release admission and let B proceed; ambiguous A failure leaves the durable slot and prevents B dispatch. Retained same-message handles, including terminal failures/timeouts, still deduplicate rather than regenerate. Ready text edits and expired storage keep the existing submission semantics.

### Miien-only speech preparation policy

[`utils/miienSpeechText.js`](../utils/miienSpeechText.js) uses an isolated instance of the already installed **Marked** and **sanitize-html**. The shared Chat5 Markdown renderer was inspected, but is an HTML/math renderer with different policies; it is neither changed nor used to mutate saved messages.

The service first reloads through the existing authorized `chat.speechText`: principal/capability at the route, owner/member conversation scope, message membership, visible assistant/text selection, and the **64,000 UTF-16-unit raw bound** all precede preparation. Preparation handles the **entire bounded reply** before taking the first **600 Unicode code points** for the sole `/tts` request to `omni_anny_en`. It repeats after final principal authorization and saved-content reload, immediately before dispatch; preview counts and fingerprint are replaced together. There is no chunking or multi-request synthesis.

| Construct | Spoken policy |
| --- | --- |
| Prose, emphasis, strikeout, nested emphasis | Keep text; strip delimiters, including literal/escaped/unmatched asterisks so `**` cannot reach Anny. Strikeout text is still spoken. |
| Headings, paragraphs, lists, quotes, tables | Keep text in source order with newline boundaries; discard markers, checkbox controls and table formatting. Quotes are prose, not instructions to execute. |
| Markdown/reference links, HTML anchors | Keep meaningful labels; discard destinations and bare/autolink URL or email tokens. Nothing is fetched. |
| Images | Omit image markup, alt text and destinations; image-only replies cannot admit speech. |
| Fenced/indented code and HTML code/pre | Omit the whole block, including an unclosed fence. Prose after a closed large code block remains eligible for the preview. |
| Inline code | Keep short simple names/phrases (at most 80 UTF-16 units); omit long spans or ones containing code operators/braces/angle brackets/newlines/URL prefixes. This is not a code or equation reader. |
| HTML and entities | Keep ordinary visible text and block boundaries; omit script/style/textarea/option/xmp/pre/code/svg/math/iframe/object content. Decode named/numeric entities once through the sanitizer, then undo its text escaping without reparsing HTML. Tags/attributes never execute and image/link URLs never load. |
| Malformed markup and controls | Best-effort parser text with residual formatting characters removed; normalize whitespace and remove control/directional formatting characters. Unmatched punctuation may remain. Tokens containing `://`, `www.` or `@` are omitted, including malformed URL-like tokens. |
| Excessive complexity | Before parsing, reject over 2,048 Markdown syntax characters, bracket/parenthesis nesting over 32, blockquote prefixes over 32 or leading indentation over 128 spaces/32 tabs. Code and URLs count toward this conservative syntax budget too. Reject rather than truncate raw Markdown or send it as a fallback. |

Dense malformed emphasis was observed to take disproportionate time in the installed parser; the syntax budget prevents that input reaching it. Bounds/parser errors produce a generic 422 and an actionable metadata-only logger warning. ### Approximate speaking synchronization

[`miien_speech_motion.js`](../public/js/miien_speech_motion.js) emits closed/small/open states at most every 80 ms. **It is a conservative speech-motion envelope, not Web Audio amplitude analysis, phoneme alignment or accurate viseme lip-sync.** It intentionally leaves the working HTML audio output graph unchanged and introduces no AudioContext activation requirement.

- Anny starts the envelope on the actual media `playing` event. Samples use `audio.currentTime` and require forward progress, ready media, nonzero volume, and no pause/end/seek/mute. A frozen clock or a time jump closes the mouth. Playback rate and replay timing follow the media clock rather than synthesis or network timing.
- `waiting`, `stalled`, `seeking`, pause, end, error, autoplay rejection, Stop, a superseding turn and page leave stop the timer and close the mouth. `seeked` resumes only for unpaused ready media, then the envelope still requires actual time advancement. Replay retains existing fresh server authorization before playback. Separate voice and timer generations reject queued stale callbacks.
- Browser speech uses elapsed time only between utterance `onstart`/`onresume` and `onpause`/`onend`/`onerror`/Stop. Browser speech exposes no PCM/media clock here. Device/OS silence and unreported pauses cannot be detected; the existing three-minute watchdog bounds a missing lifecycle event.
- The room receives small local `miien:mouth` events; the motion controller only opens a mouth in the **speaking** activity. Captions continue to render immediately when saved text arrives. No animation starts from captions, TTS submission, polling, loading or a resolved `play()` promise.

Limitations: the envelope can move through silence inside an audio file and does not track syllables, loudness or precise pronunciation. It cannot detect OS mute/output-device failure. Blink timing is a fixed repeat, and breathing is a slight whole-foreground deformation. These are explicit prototype tradeoffs for review, not claims of articulated or realistic animation.

Live2D's [lip-sync documentation](https://docs.live2d.com/en/cubism-sdk-manual/lipsync/) describes volume-driven parameter control; that does not provide Miien with aligned speech timing. The present Anny contract returns WAV without alignment; browser speech currently exposes playback events to Miien, not a PCM envelope or shared animation clock.

Keep the controller boundary stable: Chat5 owns persisted text/context/history; activity owns idle/listening/thinking/speaking; mood owns expression; the audio layer owns real playback timing and interruption. A future renderer consumes those signals without changing Chat5 persistence, inferring speech from a pending synthesis request, or overriding mood with an unrelated clip. A future timing/envelope adapter belongs at that audio/rendering boundary; it is not implemented by this documentation.

## Security contract (implementation design)

- Feature: optional Chat5 Miien character chat. Zone: logged-in. Interactive principals: admin by default; family and user require explicit grants. Machine principals: none.
- Data: private conversations and sensitive microphone audio. Capabilities: `chat.conversation.read`, `chat.conversation.write`, `chat.audio.transcribe`. Admin bundle grants all three; family/user bundles grant none. No admin object override.
- Scope: existing Chat5 member names from the validated principal, restricted to single-member conversations for this PoC. New records use the same persistence contract. No client-selected owner/member fields. Every conversation route rechecks membership. Resume supports bounded text-only Chat5 conversations without tools; no legacy conversion.
- Browser mutations: POST only, shared session CSRF token plus Origin checks. Read responses private/no-store; no analytics or third-party resources on Miien pages.
- Limits: strict allowlists; text 4,000 characters; context 4,000; 200 saved messages; context window 2–40; saved text messages at most 64,000 characters; bounded model catalog choices; one submission per conversation, at most four active submissions per process, at most two pending responses per account, durable duplicate request protection, rate limits per validated principal. Existing Chat5 provider timeouts/recovery apply.
- Output: escaped Pug attributes/text; browser textContent only; no HTML/Markdown execution, no private-media URLs. Public assets contain only generated mascot artwork.
- Microphone: canonical mono PCM WAV, 16 kHz/16 bit, at most 60 seconds/1,920,044 bytes; header and byte-count validation before ASR. Memory only; no public audio files. Existing configured ASR host only, 1 MB response limit, no redirects and no content debug logging. The original 60-second synchronous path is superseded by the queued microphone lifecycle above.
- TTS: optional browser speech synthesis placeholder, chosen device voice; no application audio upload/storage. Browser/OS voice services may process text remotely. Existing gateway TTS is deferred because its public file output and six-hour request timeout do not fit this private interactive PoC.
- Logs: actionable operational errors with category `chat5_miien` and error names, no message/audio/provider payloads. Retention/deletion: ordinary Chat5 conversation lifecycle; no separate message store. Browser audio is discarded on stop/leave; transcripts persist only when sent.
- Negative tests: anonymous/capability/foreign scope, malformed and oversized input, CSRF/origin, model allowlist, incompatible conversations, duplicate/concurrent sends, unsafe rendering, audio limits and failure fallback.
- Legacy boundary: scoped adapter around ConversationService and MessageService, existing PendingRequests/webhook/recovery execution. No new Socket.IO events, room joins, or gateway changes. Legacy Chat5 interfaces retain their existing contracts and are outside this feature's authorization perimeter; do not use both editors simultaneously.

## Architecture and persistence

`controllers/miienController.js` wires the existing database models, `ConversationService`, `MessageService`, model catalog and `AsrApiService` into `routes/miien.js`. The controller does not create a second message store. `services/miienChatService.js` owns validation, scoped loading, compatibility, settings and submission. `utils/miienAuthorizationPolicy.js`, `miienMood.js` and `miienAudio.js` isolate policy, expression rules and WAV validation.

Conversation metadata, category/tags, members, context and message IDs remain in `Conversation5Model`; text remains in `Chat5Model`. New rooms carry `chat5` and `miien` tags. History is visible through ordinary Chat5 too. Resume preserves the existing context and title: it does not silently inject the Miien persona. The Chat5 tone note and normal context selection still apply. Hidden reasoning remains provider context but is not rendered or spoken. Media, tool-enabled, shared, old-format and oversized conversations are deliberately excluded. Candidate resume links are checked again when opened.

Only the Miien adapter passes `authorizedMember` to the shared submission method. That opt-in path rechecks membership before touching messages and cannot migrate a foreign legacy conversation. It first saves the user turn, then submits generation. Failed generation leaves the saved user text in history. Retrying a network-interrupted request reuses its request ID; an accepted duplicate does not append or bill another turn. A provider failure needs a new follow-up message after reviewing history, rather than an automatic retry loop.

Optional `miienBusyUntil` and `miienRequestIds` fields on the existing conversation hold a 15-minute submission lease and at most 200 duplicate IDs. No migration/backfill is needed. PendingRequests and existing webhook/recovery workers replace hidden placeholders with final responses. One Miien submission per account and four per process may run at once; two already-pending Chat5 requests for an account block more Miien submissions. These admission limits are per process; the conversation lease is a database atomic guard. A process crash before queuing can leave a lease for up to 15 minutes. Existing Chat5 editors do not honor the new lease; simultaneous editing in different interfaces is unsupported.

Miien requests cap model output at 4,096 tokens (including OpenAI reasoning) without changing saved or ordinary Chat5 defaults. OpenAI submission has a 60-second timeout and no automatic retries. Local requests retain the existing bounded gateway job submission contract and use its runtime `max_tokens` option. High reasoning may consume the budget before visible text; use medium or low for this PoC. The provider may reject an oversized context for its own model limit. Model availability/deprecation comes from `chat5ModelCatalogService`; `DISABLE_LOCAL=TRUE` removes Local options here.

The private browser pages (`views/miien_*.pug`) use local scripts/styles only and import the shared Graphite theme directly. `public/js/miien.js` renders all conversational text with `textContent`; Markdown is displayed literally. `public/js/miien_voice.js` handles browser speech independently. `public/css/miien.css` supplies responsive layouts, visible keyboard focus and reduced-motion rules; phase 1 has no idle animation.

### Context-aware expression scoring

`classifyMood(reply, recentRows)` in `utils/miienMood.js` is a deterministic advisory rule system. It chooses art; it neither assesses a person's feelings nor changes the assistant response, prompt, metadata or shared Chat5 behavior. It needs no network, model, embedding, random selection, persistence or dependency. Existing embedding facilities were considered: `embeddingApiService` provides provider-backed retrieval/search and queued stored embeddings, not a calibrated cached mood classifier. Adding query vectors or mood prototypes would add operational work without a validated phase-1 benefit.

The snapshot adapter reads only non-hidden text by the authenticated member or `bot`, extracts nonempty string `content.text`, and restores `conversation.messages` ID order (database query/timestamp order is not conversational order). Each assistant message receives `{ id, role, text, mood }`; user messages have neutral mood. Reasoning, system/tool roles, persona metadata, empty placeholders and future turns never enter scoring. The state envelope stays `{ id, title, model, messages, pending }`; queued requests and active submission leases independently keep `pending` true.

Scoring is bounded and transparent:

- Current reply: first 8,000 characters, weight **2**. Up to three preceding visible user/assistant rows: first 1,200 characters each, newest-to-oldest weights **1, 0.35, 0.15**. At most 11,600 input characters per reply; history remains limited to 200 saved messages. There is no recursive reuse of earlier mood labels.
- Each cue family contributes once per message; each mood is capped at six points before recency weighting. Concern/distress and celebration cues score four, supportive concern and surprise score three, warmth and two explanatory/uncertainty families score two each. Repetition cannot inflate a family score.
- The highest weighted score wins at a minimum score of two. Equal scores prefer concerned, surprised, happy, then thoughtful. Mixed tones therefore resolve meaningfully rather than becoming neutral automatically. Strong current celebration can supersede earlier concern; concern can outweigh a generic polite welcome or explanatory phrasing.
- Thoughtful includes ordinary explanation, questions, comparison, planning and uncertainty: “It means…”, “The reason…”, “walk me through…”, “まず…次に…”, “仕組み”, “どうすれば”. Support, achievements, enjoyment and surprise have broader English/Japanese phrase families too. Unrecognized language/content remains neutral; there is no forced change each turn.
- Fenced/inline code, blockquotes, common English/Japanese quotation marks and explicit mood/prompt directives are excluded. Nearby English pre-negation and Japanese negative endings suppress a cue. A mood explicitly negated in the current reply, with no positive cue for that mood, cannot be resurrected by older context. Contrast clauses are evaluated independently. Explicit uncertainty/surprise idioms retain their meaning.

Limitations: these are surface cues, not semantic understanding. Sarcasm, indirect/complex negation, indirect instructions, quoted material in unsupported notation, domain-specific words and languages beyond configured English/Japanese can be misclassified. Distant context decays quickly, and content beyond the bounds does not affect art. Neutral is a valid fallback. No private production conversations were used as test fixtures. The original production diagnosis supplied by the owner identified insufficient vocabulary and missing context, not broken image loading.

The browser uses only the latest assistant mood, preloads/decodes matching portraits, guards stale decodes, normalizes unknown moods to neutral and preserves the current image on decode failure. Manual preview (including explicit neutral) persists across replies; returning to Automatic immediately restores the latest contextual selection. Unchanged polling does not rebuild transcript nodes, reset the latest-reply scroll region or re-decode the same automatic selection. Scores are recomputed locally from bounded data on state reads; there is no cross-user text cache or additional provider call.

## Voice and microphone behavior

Browser speech is an explicitly labeled phase-1 placeholder, off by default. Its voice list is the actual device/browser catalog; preferences are stored only in sessionStorage for the current tab. Enable it to speak new assistant replies. History does not autoplay on opening a room, including replies already visible while pending. Seen reply IDs prevent repeat speech after polling or history removal/reordering. Newly observed replies wait until pending clears; background or user-ended snapshots never autoplay an older reply. Replay starts from a user gesture when autoplay is blocked; Stop cancels playback. Playback is capped at 3,000 characters and three minutes; the full response remains readable. Voice errors never block sending. Selecting a voice stops existing speech. Some OS/browser voices process text remotely; voice-clone/Gateway selection is deferred.

The existing `TtsService` was inspected: it writes to `public/mp3`, can select slower clone backends, and permits six-hour requests. No fast private streaming contract was available locally, so phase 1 does not call it or change Gateway configuration. A private bounded audio endpoint should precede gateway voice selection in phase 2.

Microphone input uses MediaRecorder on a secure origin and supported browser. The client stops at 59 seconds (server limit 60), enforces a 4 MB compressed capture limit, decodes only that recording, and exports mono 16 kHz PCM WAV through Web Audio. The server validates the canonical WAV header, format, duration-by-byte-count and length, then invokes the existing ASR `/transcribe` contract with `whisper-api`, auto language, and transcription task. The response text is appended to the current draft, preserving edits made during transcription. It is never automatically sent. If the draft plus transcript exceeds 4,000 characters, the transcript is rejected with an explanation rather than silently truncated.

**Historical phase-1 behavior (superseded by the queued microphone fix above):** ASR allowed two active uploads per process and applied session/capability/membership/CSRF checks before reading audio. The configured service gets a 60-second request timeout, 1 MB response bound and no redirects. Its Miien-only private option suppresses transcript/payload debug logging. Audio stays in memory in this application and is discarded; the upstream ASR service's own retention policy still applies. Stop, leave, hiding the page, a new submitted turn or newly observed pending turn stops tracks/playback, aborts transcription, and invalidates stale callbacks. A late permission grant immediately closes its stream. Cancellation cannot guarantee that an upstream service stops work already received.

Read-only access may inspect owned compatible conversations but cannot submit/settings-write. There is no admin bypass for another member's data. Names are retained as member identifiers because that is the existing Chat5 contract; migrate the whole Chat5 identity contract to immutable IDs in a separate change.

Only artwork is public. Audio and transcripts are not written to public assets. Submitted text uses normal Chat5 persistence, embedding and response-recovery/audit retention; phase 1 is not an ephemeral/private-mode chat. Miien suppresses new ASR and LLM submission payload debug records, but the existing Chat5 response retrieval/audit pipeline still applies. Keep those database records protected by existing operational access. No credentials, account names or conversational text are logged by the new adapter's issue reports. Browser preferences store no transcript.

Cloudflare should not cache any `/chat5/miien` response; application no-store/auth/CSRF controls are effective without Cloudflare rules. No Access/WAF/Tunnel change or exemption is needed. Rollback can remove the new navigation and route mount while retaining saved conversations for ordinary Chat5. Optional lease/request-ID fields can remain unused. No destructive cleanup or migration is included.
