# Lantern Commons v1.2 security contract

All surfaces are logged-in; machine principals: none. World play retains its semantic
capability and Mongo lease. No external providers are called by these features.

- Quest: `commons.world.play`, dashboard task section policy (`dashboard.account.read`
  and `scheduletask`), plus `schedule.task.complete` for completion. Subject is the
  freshly loaded immutable account; legacy tasks remain scoped to that account's
  current canonical name, exactly as My Page. No ownerless or foreign-task override.
- Hall: current `type_user === 'admin'`, `commons.operations.read`, matching the existing
  admin-only database-usage route; no extra metric grants are required. Aggregates only, no documents,
  raw logs, user records, database names or arbitrary collection names returned.
- Shelter: current `type_user === 'family'`, OR immutable account ID
  `5dd115006b7f671c2009709d` AND current `type_user === 'admin'`; additionally
  `commons.shelter.read` and existing `emergencystock` permission. Shared household
  scope is the existing single `es_profile.key=household` inventory, not a selectable
  household. Other admins are denied regardless of grants. Normal ES routes unchanged.
- Diary: `commons.diary.write`/`commons.diary.read`, owner ID only, no admin override.
  Plain text private records, separate from Life Log, NPC prompts and world persistence.
  Retained until deliberate account-data removal; no automatic expiry or user delete API.

Admin bundles provide play/operations/diary/shelter capabilities; family and user
bundles provide diary capabilities (family also shelter), but world play remains an
explicit grant for family/user. Existing tool permissions are still required. No Chat5
grant is needed. Missing permissions deny the panel, rather than returning empty data.

Private HTTP operations require an active same-session socket generation ticket,
server proximity and fresh session/account/capability checks before work and delivery.
Tickets die on disconnect/takeover. HTTP writes use shared session CSRF middleware;
socket entry/actions use the existing CSRF handshake and configured Origin allowlist.
Role audit every three seconds ejects restricted interiors; authorization expires in
five seconds. Sensitive reads revalidate after awaits. No private payload broadcasts,
shared personal cache, localStorage, analytics or NPC context. Interior definitions are
sent only in the authorized owner's snapshot. Reconnect restores restricted scenes at
their safe public door; no authority is inferred from a saved scene.

Inputs use finite endpoints, allowlisted fields, bounded strings, 20-entry keyset
history, 64KB bodies, per-account rate limits and bounded database queries. Text uses
textContent/textarea.value only. Errors/logs contain stable operation labels and no
payload content. Private responses are no-store. Diary owner/date unique index and
revision CAS prevent overwrite; Mongo `$$NOW` date predicate fences midnight at the
atomic update. Save checks Tokyo day again immediately before DB work; database clock
is authoritative at the write, and must be synchronized with the app clock. Historical
entries are read-only. Conflicts and midnight rejection preserve the local owner-session
draft for explicit recovery. No uploads, private media, new infrastructure or migration
of old world records is introduced.

Negative tests cover roles, capability denial, owner/date scope, stale generation,
CSRF/Origin, malformed input, revision races, midnight, scene revocation, snapshots and
canonical source parity. Synthetic browser fixtures are isolated from app.js and providers.

Generic admin database list/read/delete excludes `commonsdiaries`; no browser admin override.

Release correction (client 1.2.1): every diary save verifies the actual full unique
`{ownerId:1,date:-1}` index through bounded `listIndexes`, including when automatic
indexing is disabled. Missing/incomplete indexes or metadata errors deny saving with
`DIARY_INDEX_UNAVAILABLE`; no runtime repair or destructive index synchronization.
See [index provisioning and bounded timing semantics](V1.2-RELEASE-REVIEW.md).
