## Findings corrected

1. **Release blocker: diary uniqueness was not enforced with `autoIndex:false`.**
   `model.init()` can complete without creating the unique index. Competing first
   saves could therefore upsert duplicate owner/date records. Every save now checks
   the actual Mongo index metadata before reauthorizing and writing. Missing,
   nonunique, partial, sparse or extra-key indexes, and metadata errors, fail closed.
   HTTP 503 `DIARY_INDEX_UNAVAILABLE` explains setup and retains the draft. Production
   logging names the required index and handoff, with no text or raw DB errors.
   The warning is throttled to once per minute per diary service instance.
2. **Static cache mismatch:** the existing immutable-art rule covered `.v1.webp`
   but omitted `furnishings.v1.2.webp`. The rule now covers both versions. Client,
   script and style revision is **1.2.1**, forcing stale clients to reload.
3. The browser review script accepts the existing `COMMONS_SCREENSHOTS` convention,
   allowing a fresh review without overwriting original evidence. Added regression
   tests also cover missing-index HTTP/UI recovery, leap-calendar validation, and
   delayed quest/stock/diary responses after scene changes and permission revocation.

No art, existing collider/crop definitions, dependency, normal admin-page behavior,
canonical My Page adapter, ES calculation or account configuration was changed here.

## Security and behavior audit

**Diary.** `CommonsDiary` / `commonsdiaries` has immutable ObjectId `ownerId` and ISO
`date`, unique `{ownerId:1,date:-1}`, plain `text`, numeric `revision`, and `updatedAt`.
Every exposed entry query includes the freshly authorized immutable owner ID. No
client owner selector, delete operation or admin override exists. The private API
requires an active same-session socket ticket and proximity inside the owner's
cottage. Generic admin collection list/read/delete deny exactly `commonsdiaries`;
unrelated collections remain available, including existing Accounting read-only rules.
The database-usage page exposes collection-level storage/count metadata, not documents.
Legacy embedding search resolves a fixed three-model map; other embedding sources
and export routes do not ingest diary entries. No entry text is added to world state,
snapshots, socket rooms, NPC context or production logs. Offline DB operators/backups
remain outside browser-level owner isolation; this is not encryption from DB operators.

The save accepts only `{date,text,revision}`: 10,000 UTF-16 code units, revision integer
0–1,000,000,000, real ISO calendar date. History uses descending date keysets, 20 dates
per response (21 fetched to find the next cursor), with no entry text in history lists.
There is one document per owner/date when the required index exists; no automatic
retention expiry or maximum lifetime page count. HTTP bodies are capped at 64KB,
private operations at 60/account/minute and one pending request/socket connection.
Reads/updates/index inspection use 2-second Mongo limits. Text remains literal even
when it begins with `$` or contains HTML.

Tokyo today is server-derived, not browser-derived. Save checks it before index work
and after fresh authorization. The Mongo pipeline separately compares the requested
date to the command's stable `$$NOW` in `Asia/Tokyo`, aborting stale inserts and updates.
**Bounded semantics:** an operation accepted with a pre-midnight command timestamp may
complete or acknowledge after midnight; this is not a commit-time wall-clock fence.
Execution and majority write-concern timeouts are 2 seconds. A write-concern timeout
can leave an accepted write committed; reload/revision conflict reconciles uncertain
retries without blindly overwriting it. Keep app and DB clocks synchronized. Index
metadata checking is not transactional with external administrative index DDL; keep
DDL offline while saves are enabled.

Past pages are readable, never writable through this API. At midnight, a stale save
shows the date-change message and retains the draft; Load today starts today's page
and presents the old draft separately for copying. Close/Escape and reconnect retain
page-memory drafts for the same owner/session. Account/session switch clears them;
refresh/tab closure is not durable draft storage and triggers a warning when possible.
Movement is blocked while a modal/editor is open. No localStorage is used.

**Shelter.** `type_user` is the canonical account type; Manage Users displays lowercase
`family` as Family. Editable role names, labels and an ID alone do not establish
eligibility. The only alternative is ID `5dd115006b7f671c2009709d` while its current
`type_user` is `admin`. Other admins are denied even with Shelter grants. No live
account's current type or assigned grants were inspected during this review.

Private stock reads reuse `buildEmergencyStockSnapshot`, the same pure calculation as
`/es/es_dashboard`. The ES model is one site household (`es_profile.key=household`),
not a selector for arbitrary ownerless data. Reads cap at 200 categories/2,000 items
and require the profile; overflow/missing profile fails visibly. Domains retain water
litres, food person-meals, toilet uses and medication days. Individual non-pooled
categories retain their units; equipment uses inspection-ready amounts. Percentages
are uncapped to one decimal: 60/45 L = 133.3%; zero current = 0%; no positive target,
non-finite or unknown readiness = unavailable. The visual bar caps at 100. Decorative
jars/sacks/chest are static artwork, not a live quantity display. Quantities and deficits
stay in the authorized panel, never public snapshots, logs or public error bodies.

**Quest board.** It calls the actual `createDashboardData().load('tasks', policy)`
adapter, identical to `/mypage/api/cards/tasks`. It preserves `todo` and `tobuy`,
`done:false`, availability now/within 14 days, source caps 12 overdue/12 today/16 other,
and canonical status/planning-date/ID order. Page flipping covers this result, not an
unbounded server task list. Optional Accounting reminders can add up to 100 entries.
Those are explicit **Review and confirm in Accounting** links, never a Done mutation;
financial close/review records cannot be forged into normal task completion.

Completion uses the canonical conditional update and current authenticated name,
`_id`, and allowed task types. Foreign, absent, ownerless and presence records fail.
Retries do not retimestamp an already completed task; pending-reminder deletion can
repeat safely to recover a cleanup failure. No financial workflow is completed by it.
**Legacy limitation:** task ownership is the current canonical username, not an
immutable task-owner ID. This preserves the established My Page semantics. Duplicate,
renamed or recycled account names require separate legacy identity/data reconciliation;
this review makes no claim of isolation across such identity changes and performs no
migration or live-account alteration. Diary/Shelter identity does not use names.

**Hall.** Eligibility is authoritative current admin plus `commons.operations.read`.
Both shelves enforce it before reads and after awaits. The selected metrics are a
bounded read-only subset of the already admin-only `/admin/database_usage` source;
that source has no additional per-stat capability. There are no arbitrary model names
or content/log projections. Commons diagnostics project only initialized/online/lease/
save-failure/revision/last-save fields, with a current-worker note.

| Label | Exact collection | Meaning |
| --- | --- | --- |
| Chat5 conversations | `conversation5` | All retained conversation documents |
| Chat5 messages | `chat5` | All retained message documents |
| Knowledge records | `chat4_knowledges` | All retained knowledge documents |
| Saved GPT images | `gpt_image_generations` | Saved output records, not unique jobs |
| Saved music outputs | `musicgenerations` | Saved output records, not provider jobs |

Each uses `collStats.count` with a 2-second limit, no date/status/deletion filter and no
personal content. Deleted Mongo documents no longer count; a retained record whose
media file was removed still counts. These are archive sizes, not media availability
or completed-job statistics. Per-source failures show unavailable, not zero. Open and
Refresh read again and display read time; the five reads are not a cross-collection
transactional snapshot. Synthetic real-Mongo verification inserted two records per
collection and obtained five counts of 2. Browser fixtures deliberately display 42.

**Transitions/private delivery.** Server room actions retain cottage ownership and
restrict Hall/Shelter entry. Scene transforms, persistence and takeovers use the room's
serial queue. Private responses freshly recheck the session/account/capabilities,
current connection and display proximity after awaited work. Browser generations
suppress late replies after close, scene changes, authorization reset or takeover.
Audits run every 3 seconds and authority expires after 5 seconds: revocation is bounded,
not instantaneous. Restricted saved scenes restore at outdoor exits before the first
snapshot even for formerly authorized accounts. Interior snapshots are isolated; no
other resident's interior is broadcast. Private facades remain visible outdoors and
return access-unavailable on interaction; this presentation is intentional.
