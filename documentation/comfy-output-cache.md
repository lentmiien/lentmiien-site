# ComfyUI output identity and recovery

The site used to identify generated output by basename (and sometimes instance),
so `folder-a/same.png` could silently reuse `folder-b/same.png`. Gateway status and
its download descriptor were correct; the site skipped the download. Workflow
prefix changes are independent defense in depth and are not required by this fix.

## Identity and compatibility

The v2 identity includes the configured Gateway origin/path, instance namespace,
Gateway job ID, output array index, node ID, and validated filename/subfolder/type.
The site fetches using that descriptor, not a potentially conflicting view URL.
Filenames are display metadata; an opaque SHA-256 identity selects the local file.
Duplicate basenames within a job retain their original indices, including failed
outputs. Downloads never select a file using a request-supplied filename.

New bytes are stored in `private_data/comfy-output/v2/`. Writes publish atomically
without overwriting an existing identity. Concurrent requests coalesce. URLs use
`/image_gen/api/jobs/:id/files/:index?cache_key=<identity>` (plus `instance_id` where
applicable); the key must match the selected output. Responses use private/no-store.
No absolute local paths are returned. The existing `files`, `filename`, `index`,
`cached`, `cached_url`, `download_url`, `subfolder`, `type`, and `node_id` contract
is retained; local URLs change. Clients must use the returned URLs. Raw Gateway
view URLs are no longer a result-display fallback.

The legacy `/api/jobs/:id/images/:index` alias remains. Basename-only
`/api/files/output/:filename` and `/api/files/video/:filename` return 409: callers
must use job-file URLs. Input browsing is unchanged. Promotion remains disabled.
Favorites copy the verified output selected by index, never a basename lookup.
Existing saved favorites retain their old storage and URLs.

Bulk records retain `filename` as display metadata and persist `output_file` with
the full versioned identity. All bulk views, analytics, comparisons, scoring,
slideshow, and thumbnails resolve that identity. They never trust an old
`file_url`. Existing bulk hydration also attempts to recover completed legacy
records from Gateway job status, bounded to 50 records per page operation. A
failed repair leaves the old record untouched and displays no unverified bytes.
A verified bulk descriptor can serve local bytes after Gateway history expires.

Completed in-memory jobs are reusable only when their versioned identities and
local files are verified. Instance namespaces have separate memoization. Failed
caching is retried on status retrieval, and the browser keeps polling within its
existing bounded polling lifetime rather than declaring uncached files final.

## Security contract for the corrected output cache

- Zone/principals: logged in; existing site session, no new machine callers.
- Capability: `comfy.outputs.read` for status and both job-file route aliases.
  Admin receives it in the explicit capability bundle; family/user do not receive
  it by default. A deliberate semantic grant uses the existing capability system.
  Existing parent `/image_gen` authorization remains required.
- Object scope: explicitly admin-managed shared Gateway output library. A grant
  authorizes that entire library, not personal jobs. Gateway/legacy records do not
  establish reliable individual ownership. Bulk thumbnails retain `comfy.bulk.read`
  and their parent/child checks. There is no implicit role-based owner override.
- Classification: private generated output. New output storage is outside public;
  private delivery is capability checked, no-store, and nosniff. The old public
  cache and saved-favorite gallery are legacy dependencies, not migrated here.
- Browser mutations/CSRF: no new mutation routes; status/file reads materialize
  only a derived cache. Generation, rating, and bulk operations keep their legacy
  contracts. This is an output-cache correction, not a replacement of those APIs.
- Validation/work: filenames must be a supported media basename; subfolders must
  be bounded relative components, without traversal, controls, percent encoding,
  backslashes, or drive prefixes. Types are output/temp/input. Indices and output
  counts are bounded to 10,000, five cache operations run at once, and at most 32
  wait. Gateway downloads retain their timeout and reject bodies over 512 MiB,
  including chunked responses. Busy/failed outputs remain uncached and retryable.
- Files: server-derived hashed names; configured-root realpath and symlink checks;
  atomic publication without replacement. Original remote paths never become
  local filesystem paths. Browser URLs are generated by the site.
- Outbound service: the configured Gateway only; the validated descriptor supplies
  the query, redirects are rejected. Instance IDs separate identity; the Gateway
  still supplies its existing single configured ComfyUI backend, not an arbitrary
  caller-chosen destination.
- Logs: stable validation/cache/recovery failure messages, operation/index and
  bounded diagnostic codes; no prompts, images, descriptors, or view URLs in the
  new cache logs. Download/status errors are generic to clients.
- Retention: durable cache; no automatic deletion added. Back up the new private
  directory with the site's other private media. Keep it out of source control,
  static mounts, and public sync. Existing bytes are not relabeled or purged.
- Negative coverage: missing login/capability, mismatched output key, index and
  descriptor validation, traversal/symlinks, wrong instance/job/provider, failed
  download, stale basename/persisted bulk URL, and unavailable Gateway recovery.

## Deployment and safe recovery

No production changes are part of this implementation. No environment variables,
workflow changes, destructive cache purge, or database migration command is needed.
The new nullable `output_file` field is additive.

1. Deploy the commit through the normal application deployment and restart every
   web/worker process on the new revision. This clears old in-memory terminal
   results and avoids old workers continuing to create basename-only records.
2. Ensure the application account can create/write `private_data/comfy-output/v2`
   and include it in private-media backups. Do not configure a static route or
   public CDN cache for this directory or `/image_gen/api/jobs/`.
3. Sign in with the administrative account. Non-admin operators explicitly
   authorized for the shared library also need `comfy.outputs.read` in addition
   to their existing image-gen/bulk permissions. Reload the page to load the new
   polling JavaScript.
4. If an affected job is still selected on `/image_gen`, click **Poll status**.
   For any other affected job, open the authenticated
   `GET /image_gen/api/jobs/<URL-encoded-original-job-id>` endpoint in the browser.
   The current UI job-ID field is read-only; use that endpoint for older job IDs.
   Include the original `instance_id` query only if that job used one.
5. Confirm the returned output descriptor has the expected subfolder and filename,
   `cached: true`, and a job-file `cached_url` with `cache_key`. For the reported
   incident, the subfolder must be `Qwen-Image-2.1-Uncensored`, with the respective
   `edit-2ref_00002_.png` or `edit-2ref_00003_.png`. Open/download the returned URL.
   Old `/imgen/edit-2ref_...` links remain legacy links and must not be used to
   verify recovery. Browser/CDN purges of those links are unnecessary.
6. Open affected bulk job pages to invoke bounded legacy descriptor recovery.
   Verify that `output_file.cache_version` is 2 and returned file URLs are job
   URLs. Unrecoverable records stay untouched. If a batch is blocked by expired
   Gateway history, restore that history from an authoritative backup before
   retrying; do not substitute a same-named local file or hand-stamp cache_version.

Neither affected job had a saved favorite according to the production evidence,
so there are no favorite records to repair for those two jobs. This fix does not
rewrite any previously saved favorite. Existing favorites of uncertain provenance
require separate source verification; never replace them based on basename alone.

## Limits and rollback

Recovery needs authoritative Gateway descriptors and the original remote bytes.
If Gateway history is gone, or ComfyUI has overwritten/deleted the actual remote
file, the site cannot establish the original output from an old basename cache.
Restore authoritative history/files from backup or regenerate; never rename old
bytes as the corrected output. Unique workflow prefixes help prevent remote
ComfyUI overwrites, which a site cache identity alone cannot solve.

Interactive job metadata/rating context remains in memory as before. After a
restart/history expiry, an interactive job without persisted metadata may be
unavailable even if its private cache bytes remain. Its favorite rating window
also remains transient. Bulk records with v2 descriptors retain local download
access independently of Gateway history. The identity URL remains stable while
its verified cached bytes are retained; manually deleting the private cache can
force retrieval of whatever bytes the remote descriptor currently represents.

Rolling back reintroduces the collision bug. The additive bulk field and private
cache can remain on disk/database, but older code does not understand them. Keep
new private media and backups; do not copy them into the old basename namespace.
